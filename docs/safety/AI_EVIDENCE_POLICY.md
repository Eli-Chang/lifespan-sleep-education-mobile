# AI Evidence Policy

## Scope and status

The Worker may use only excerpts in `cloudflare-worker/evidence/`. The current bank is a versioned copy of existing project educational content and is marked `pending-research-team-review`. `EVIDENCE_BANK_ENABLED` defaults to `false`; the Worker fails closed with an unsupported-material response until the research team approves a version and an authorized operator explicitly activates the matching version. No entry is marked clinically approved.

## Approval authority

The research team, with the institution's designated clinical/content approver, must approve each statement and its English/Spanish pair before activation. Codex has not completed that approval. The approval record must identify the reviewer, date, source version, exact statement, allowed use, prohibited interpretation, and effective/retirement dates.

## Versioning and retirement

Each entry has a stable `source_id`, topic, exact approved text, source title/location, version, locale, and review status. A new source version creates a new bank version and preserves the old version for audit history. Obsolete or superseded statements are removed from the active manifest only after a documented replacement/retirement decision. Never silently edit an active statement.

## Citation mapping

The model receives only relevant bank entries. It must return `source_ids`; the Worker rejects IDs not present in the supplied evidence set and rejects `evidence_sufficient: true` with no source IDs. Unsupported responses return an empty source list and `evidence_sufficient: false`. The client never invents or displays citations.

## Unsupported and unsafe questions

When no active evidence is available, or the evidence is insufficient, the Worker returns the existing bilingual unsupported-material fallback and `needs_clinician: true`. Prompt injection, diagnosis, medication, PAP-pressure, individualized pregnancy-management, emergency-assessment, and source-document requests are refused or routed to fixed approved language. Emergency language is deterministic and is not generated by Groq.

## English/Spanish alignment

Each educational statement has an English/Spanish pair where the existing project content provides both. The research-team approval record must review both languages for meaning parity and safety wording. A translation is not clinically approved merely because it is present in the repository.

## Activation checklist

1. Research team approves the exact version and statement pairs.
2. Clinical/AI-safety reviewer approves boundaries, unsupported behavior, and urgent copy.
3. Privacy/security review confirms vendor, retention, and logging terms.
4. Authorized operator sets the matching Worker evidence activation variables in a separate approval change.
5. Tests validate every returned source ID and every evaluation case before any deployment.
